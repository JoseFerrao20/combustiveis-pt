# combustiveis-pt

Pipeline de dados com os preços semanais dos combustíveis em Portugal e na UE (Weekly Oil Bulletin da Comissão Europeia, desde 2005): ingestão em Python para Parquet (`src/combustiveis/`), depois dbt com DuckDB e um painel com Evidence (`dashboard/`, publicado no GitHub Pages pelo `pages.yml`). Projeto de portfólio de José Ferrão. A escolha da fonte está em `docs/adr/0001-fonte-weekly-oil-bulletin.md`; o histórico e o plano em `DEVLOG.md`.

## Comandos

```bash
uv sync --all-groups                           # o grupo transform traz o dbt
uv run pytest                                  # cobertura ≥ 90 %
uv run ruff check . && uv run ruff format --check . && uv run mypy
uv run combustiveis ingest                     # precisa de acesso a energy.ec.europa.eu
uv run combustiveis ingest --ficheiro tests/fixtures/oil_bulletin_sample.xlsx   # sem rede
uv run combustiveis dgeg [--ficheiro tests/fixtures/dgeg_sample.json]         # fotografia dos postos (DGEG)
uv run combustiveis verificar-dgeg [--pasta data/landing/dgeg] [--idade-maxima 8]   # histórico da DGEG em dia
uv run combustiveis mercados [--ficheiros tests/fixtures/fred]                # cotações e câmbio (FRED), para a previsão
uv run combustiveis ilhas [--pasta data/landing/ilhas]                        # preços máximos dos Açores e da Madeira (despachos novos em PDF)
uv run combustiveis verificar-ilhas                                            # há o preço da semana (Madeira) e do mês (Açores)?
uv run combustiveis telegram [--enviar]                                        # avisos de segunda-feira (TELEGRAM_SUBSCRIPTIONS e TELEGRAM_BOT_TOKEN; sem --enviar, só mostra)
uv run combustiveis verificar-site --url https://joseferrao20.github.io/combustiveis-pt/   # o site publicado está em ordem?
uv run combustiveis site                                                       # depois do dbt: os JSON da página inicial (dashboard/app/public/dados/), as páginas por concelho, o sitemap.xml e os dados abertos
uv run python scripts/fit_forecast.py [--gravar]                              # coeficientes da previsão (depois do dbt, com os dados reais)
uv run dbt build --project-dir transform --profiles-dir transform   # da raiz; LANDING_DIR, DGEG_DIR, DUCKDB_PATH e *_EXPORT_PATH mudam os caminhos
cd dashboard && npm ci && npm run sources && npm run build   # site (Evidence e página inicial, Node 22), depois do dbt e do `site`
cd dashboard && npm run dev:inicio                            # só a página inicial (Vite), com os JSON do `site`
cd dashboard && npm test                                      # Playwright sobre o build (tests/serve.mjs serve /combustiveis-pt/)
```

## Convenções

- README, DEVLOG, ADR, mensagens de erro e descrições de PR em **português de Portugal**; nomes no código e mensagens de commit em inglês.
- Cada alteração num PR a partir de um ramo, com o CI verde.
- O formato do ficheiro do boletim não está documentado: a leitura (`parse.py`) valida-o e lança `FormatError` em vez de devolver dados errados. Os testes usam `tests/fixtures/oil_bulletin_sample.xlsx`, uma amostra do ficheiro real gerada com `scripts/make_sample.py`: se o formato mudar, gerar outra a partir do ficheiro novo.
- Valores por 1000 L (por tonelada nos fuelóleos). Nas folhas de impostos, uma célula vazia é "sem dados", não zero. O ISP e os outros impostos estão na moeda nacional (escudos antes de 2002).
- O link do ficheiro muda quando a Comissão o substitui: procurar sempre na página (`source.find_history_url`), nunca fixar o endereço.
- `data/` não entra no Git.
- DuckDB 2: as relações já não têm `fetchone()`; usar `fetchall()`.
- dbt (`transform/`): staging e intermediate são views, marts são tabelas. Testes com a sintaxe `arguments:` do dbt 1.10+. Os testes guardam as linhas que falham (`store_failures`), para se verem no DuckDB. Um erro na fonte não se corrige nos dados: entra no seed `known_source_errors` com a explicação, depois de visto.
- As tabelas de ISP e outros impostos só se comparam com o preço a partir de `countries.euro_since` (antes, estão na moeda nacional). A decomposição (`fct_fuel_prices`) vem dos preços e do IVA; as tabelas só dão o `tax_tables_gap`. Os períodos em que as tabelas estão erradas, já investigados, ficam no seed `known_tax_table_issues` (país, produto, de/até, explicação; sem sobreposições) e aparecem em `tax_tables_issue`; o aviso `warn_tax_tables_explain_price` (PT, LT, NL, SK e ES) ignora-os e está a zero: uma linha nova é uma semana a investigar. Análises em `docs/analises/`.
- DuckDB: um alias de coluna precisa de `as` quando o nome é uma palavra-chave (`count(*) as weeks`).
- Painel (`dashboard/`, ADR 0002): Evidence open source 40.1.8, versões fixadas; já não recebe novidades (a empresa passou para o Evidence Studio). Lê só os Parquet que o dbt exporta (modelos `rpt_*` em `transform/models/reporting/`: `data/road_fuel_prices.parquet`, `data/stations_latest.parquet`, `data/station_prices_daily.parquet`, `data/tracked_stations_daily.parquet`, `data/tracked_station_competitors.parquet` e `data/price_forecast.parquet`), porque o DuckDB do Evidence (1.4) não abre a base de dados do DuckDB 2. Uma coluna nova para o painel entra nesses modelos. O Evidence descarrega cada fonte inteira em todas as páginas e guarda no site o resultado de cada consulta (`api/prerendered_queries/*.arrow`): fontes pequenas (o `rpt_road_fuel_prices` só leva o histórico de PT, ES e UE e a última semana dos outros países) e consultas só com as colunas precisas (nada de `select *` em consultas intermédias como `zona`). O `npm run sources` e o `npm run build` precisam de `extensions.duckdb.org` (o DuckDB-WASM descarrega aí a extensão de Parquet): sem acesso, ficam parados em vez de falhar. Nas sessões cloud, com o proxy, correr com `NODE_USE_ENV_PROXY=1 NODE_EXTRA_CA_CERTS=/root/.ccr/ca-bundle.crt` (o Node não usa o `HTTPS_PROXY` sem isso). O `typescript` fica na 5.4.2, a versão que o Evidence pede.
- O site está em `/combustiveis-pt` (`deployment.basePath`). Aspeto comum: o cabeçalho (`components/Cabecalho.svelte`: ícone, nome e os links Início, Resumo, Postos acompanhados, Açores e Madeira e Análises, com "Menu" até 760 px) e o rodapé (`components/Rodape.svelte`) são os mesmos na página inicial e no Evidence; o `+layout.svelte` esconde o cabeçalho e a barra lateral do Evidence (`hideHeader`, `hideSidebar`, `maxWidth={1120}`). O botão do tema (no cabeçalho e nas páginas por concelho) troca o claro e o escuro: muda o `data-theme` do `<html>` e guarda em `evidence-theme`, a chave do Evidence (que segue o `data-theme`). Uma página nova do Evidence entra nos links do cabeçalho se for de topo; as análises abrem pelos cartões de `analises/index.md`. Nos links em HTML (cartões), o caminho vai completo (`/combustiveis-pt/…`): o Evidence só junta o `basePath` aos links em Markdown. Cartões (`.cartoes`, `.cartao`, `.cartao-titulo`, `.cartao-numero`, `.cartao-texto`, `.seta-baixo`/`.seta-cima`) e conclusões (`.conclusao`) têm o CSS no `+layout.svelte`; as frases dos cartões fazem-se em SQL com a pontuação, porque o `Value` deixa um espaço a seguir. As tabelas secundárias ficam em `<Details>`. No DuckDB, um alias da mesma `select` não se reutiliza numa expressão com subconsulta: usar uma consulta à volta.
- Página inicial (ADR 0005): não é do Evidence. É `dashboard/app/` (Vite e Svelte 4, as versões que o Evidence traz, fixadas nas `devDependencies`), com o mesmo `components/MapaPostos.svelte` (só a página inicial o usa). A página passa ao componente o combustível (slot `combustivel`, ao lado de "Perto de mim") e o distrito e o concelho (slot `zona`, dentro do "Filtros", um `<details>` com a marca, as autoestradas e, com a localização, o depósito e o consumo; `zoneFilters` conta os filtros da zona escolhidos para o resumo do "Filtros"). A previsão é uma linha (`forecast_summary` do `resumo.json`) que abre o texto todo. O cabeçalho é uma linha com "Menu" no telemóvel. Lê `dados/resumo.json` e `dados/postos-<combustível>.json`, escritos pelo `combustiveis site` (`site.py`, a partir de `stations_latest.parquet` e `price_forecast.parquet`; colunas em `COLUMNS`, horas com `Z` como o Evidence as dá). O `npm run build` faz o build do Evidence e depois o `build:inicio`, que escreve o `index.html` da raiz e `inicio/` no mesmo `build/`. O `pages/index.md` do Evidence só existe para os links "Início" das páginas do Evidence (que mudam de página sem a carregar): pede a página ao servidor. Resumo e postos acompanhados (ADR 0006): também fora do Evidence, em `app/resumo/` e `app/acompanhados/` (o Vite faz o build das três páginas, `rollupOptions.input`; código comum em `arranque.js`, o tema e o service worker, e `formatos.js`, os números, as datas e o `lerJson`). O resumo calcula as médias no browser a partir de `dados/postos-<combustível>.json` (por isso o `COLUMNS` leva `brand_segment` e `competitors_5km`) e a evolução de `dados/evolucao.json`; os postos acompanhados leem `dados/acompanhados.json`. Os dois JSON vêm do `combustiveis site` (`export_history`, `export_tracked`, a partir de `station_prices_daily`, `tracked_stations_daily` e `tracked_station_competitors`; sem os Parquet, não os escreve). Os gráficos são `Grafico.svelte` (SVG, com os valores numa tabela `sr-only`); os filtros são `<select>` nativos com `label` (nos testes, `getByRole('combobox', { name: 'Distrito' })`). O CSS destas páginas (`.pagina`, `.filtros-pagina`, cartões, `.tabela`) está em `app/src/base.css`. Açores e Madeira (ADR 0007): `app/ilhas/`, com `dados/ilhas.json` (`export_islands`, de `island_prices.parquet`). Um `.sr-only` nunca vai numa `<table>` (uma tabela não encolhe para 1 px e a página passa a deslizar para o lado no telemóvel): vai numa `div` à volta. No cabeçalho, os links para páginas fora do Evidence têm `rel="external"` (só "Análises" fica sem, `evidence: true`). O CSS da página inicial (`app/src/base.css`) tem as cores dos temas do Evidence e as classes do Tailwind que o componente usa; uma classe nova no componente tem de entrar lá. O componente não pode usar nada do Evidence além do store `data`. Links: a página inicial aceita `?posto=<id da DGEG>`, `?combustivel=`, `?distrito=` e `?concelho=` (aplicados depois de ler o resumo; o concelho escolhe também o distrito). Um posto do link abre o balão, sem a localização lembrada; "Partilhar" (no balão, `partilhar`) usa o `navigator.share` ou copia o link. Páginas por concelho (`pages.py`, escritas pelo `combustiveis site` em `app/public/concelho/`, pasta apagada e refeita em cada execução, e `app/public/sitemap.xml`): HTML estático com os 10 mais baratos de cada combustível, a data e a hora de cada preço (termos da DGEG), as médias do concelho, do distrito e do país e "Ver todos no mapa" (`?concelho=`); o estilo está em `static/concelho/estilo.css` (o Evidence copia-o para o `build/`). Dados abertos (`opendata.py`, em `app/public/dados-abertos/`, com `--armazem`, por omissão `data/warehouse.duckdb`; sem ele, não se escrevem): `postos-historico.csv.gz` (todas as fotografias, `fct_station_prices`), `postos-ultima-fotografia.csv` e `boletim-europeu.csv.gz` (`fct_fuel_prices`, com os valores arredondados a 2 casas e as partes a 4), e a página com as colunas, as fontes e como citar (feita com o `_page` das páginas por concelho). O link "Preços por concelho" do rodapé tem `rel="external"`: sem isso, o build do Evidence segue-o e falha com 404, porque as páginas só entram depois, com a página inicial. Instalar como aplicação: `app/public/manifest.webmanifest` (nome, `start_url`, `display: standalone`) substitui no build o manifesto que o Evidence gera. Pouca rede: `static/sw.js` (a página inicial, as páginas leves de `LIGHT_PAGES` e os `dados/*.json`: rede primeiro, sem a cache HTTP; o que ficou guardado se falhar ou demorar 4 s, com o cabeçalho `x-combustiveis-guardado`; os ficheiros de `inicio/` primeiro da cache). O patch do `core-components` faz o Evidence registar o `sw.js` em vez do `fix-tprotocol-service-worker.js` (os dois no mesmo âmbito substituíam-se); o `sw.js` tem a mesma correção para os Parquet no Windows. Nos testes, o modo offline do Playwright nem sempre chega ao service worker: a página também mostra o aviso com `navigator.onLine` falso, e o teste confirma o que ficou na cache.
- Agendamento: o `pages.yml` corre todos os dias (cron em UTC) com `ingest --idade-maxima 15`, que falha se o boletim tiver parado. Uma falha não publica nada: o site fica com a última versão boa. Depois do deploy, o trabalho `verificar` corre `combustiveis verificar-site` (`live.py`) com o endereço publicado: a página inicial, `dados/resumo.json` com uma fotografia de no máximo 8 dias e postos em todos os combustíveis, o JSON do primeiro combustível com os postos que o resumo diz, `resumo/`, `concelho/`, `dados-abertos/` com o link do histórico, o `sitemap.xml` com os concelhos, `sw.js` e o manifesto. Junta todos os problemas numa mensagem (o email do GitHub). Os pedidos usam o `fetch_with_retries`; nos testes, o `fetch` é um site em memória.
- Açores e Madeira (ADR 0007, `ilhas.py`): a DGEG só tem o continente; nas regiões autónomas há um preço máximo da gasolina 95 e do gasóleo, fixado pelo governo regional e publicado em PDF. Madeira: despacho conjunto semanal na II série do JORAM (quase sempre num suplemento de sexta, mas pode sair noutro dia), em vigor na segunda; lê-se a lista de cada ano (`MADEIRA_LISTING`) e, de cada PDF novo, primeiro só o sumário (`SUMMARY_PAGES`, há números com dezenas de MB). Açores: despacho normativo mensal na I série do Jornal Oficial, em vigor no dia 1; o site tem uma verificação anti-robôs (não contornar), mas os PDFs dos números têm endereços sequenciais (`ACORES_ISSUE`, `I-AAAA-NNN-S0.pdf`, com o índice e os atos), seguidos até ao primeiro 404. Texto com o pypdfium2 (`pdf_text`, numa linha e em minúsculas), frases fixas em expressões regulares, preços validados (`PRICE_RANGE`) e a data de entrada em vigor face à publicação; o que não se lê lança `IslandFormatError` e o `update` para antes desse ficheiro (o estado fica lá, para o reler depois de corrigido). Histórico no ramo `dados` (`ilhas/precos.csv` e `ilhas/estado.json`), escrito pelo `ilhas.yml` todos os dias, que depois corre `verificar-ilhas` (falha sem o preço da semana na Madeira, mais de 8 dias, ou do mês nos Açores, depois do dia 3); o `pages.yml` tira-o do ramo, ou escreve um CSV só com o cabeçalho. dbt: fonte `ilhas` (`ILHAS_DIR`), `stg_ilhas__max_prices` e `rpt_island_prices` (com o preço médio dos postos do continente na última fotografia de cada período). O CI usa `tests/fixtures/ilhas/precos.csv` (despachos reais de setembro a novembro de 2026). Nos testes, os PDFs fazem-se com `make_pdf` (Helvetica com WinAnsi, que tem o € e os acentos).
- Avisos pelo Telegram (`telegram.py`, guia em `docs/telegram.md`): o `pages.yml` corre `combustiveis telegram --enviar` só a seguir a uma fotografia da DGEG bem tirada (`workflow_run` com `conclusion == 'success'`), com `continue-on-error` (o Telegram não impede a publicação). As inscrições estão no segredo `TELEGRAM_SUBSCRIPTIONS` (JSON: `chat_id`, `combustivel`, `postos`, `distrito`) e o token em `TELEGRAM_BOT_TOKEN`; sem eles, não envia nada. A mensagem é texto simples (o Telegram faz os links), com a previsão, os postos seguidos (preço, mudança na semana, posição a 5 km em haversine, como no site) e o mais barato do distrito (`of_district`: "do Porto", "da Guarda"). O envio continua se uma mensagem falhar e diz no fim quais falharam. Nos testes, o `_post` é simulado; a função escolhe-se dentro do `send` (`post=None`), para o `monkeypatch` a trocar.
- Números do painel em português (`2,099 €`, `58,8%`): o `ssf` do Evidence não tem locales, por isso há um patch (`dashboard/patches/`, aplicado pelo `patch-package` no `postinstall`) que troca os separadores na formatação dos números. Se a versão do `@evidence-dev/component-utilities` mudar, o patch tem de ser refeito. As cores das séries estão nas páginas (`seriesColors`, `colorPalette`), e o título e o link do repositório em `pages/+layout.svelte`.
- Ver o painel: depois do build, servir a pasta pai de um link `combustiveis-pt → dashboard/build` (`python3 -m http.server`) e abrir `/combustiveis-pt/`; as páginas são pastas (`analises/comparacao/`). Páginas: a página inicial (`app/`, os postos, a página para a família e os amigos), o resumo e os postos acompanhados (`app/resumo/`, `app/acompanhados/`, fora do Evidence) e a pasta `analises/` do Evidence (impostos, previsão, comparação com a Europa e método, abertas pelos cartões do `analises/index.md`). Os endereços antigos (`postos/`, `comparacao/`, `metodo/`) redirecionam com páginas HTML em `static/`. Uma página sem consultas faz o Evidence pedir um `all-queries.json` que não existe (404 nos testes): pôr pelo menos uma consulta.
- Interface em português: o patch `dashboard/patches/@evidence-dev+core-components+5.4.2.patch` traduz o menu ("Aspeto", "Imprimir em PDF"), a pesquisa e a paginação das tabelas e o "Feito com o Evidence"; o `@evidence-dev+evidence+40.1.8.patch` põe `lang="pt-PT"` no `app.html`. O `+layout.svelte` tem `neverShowQueries` (esconde "Show Queries"). Textos novos do Evidence em inglês entram nesses patches (editar em `node_modules/` e correr `npx patch-package <pacote>`). As capturas do README (`docs/images/painel-*.png`, 1280×860, tema claro) tiram-se assim com o Playwright. A barra lateral usa o `title` de cada página; o CSS em `+layout.svelte` tira o `capitalize` do Evidence, e o caminho de navegação está desligado (dizia sempre "Home").
- Postos (ADR 0003): `combustiveis dgeg` lê a API JSON da página de pesquisa da DGEG (`/api/PrecoComb/PesquisarPostos`, sem documentação), num pedido só (com novas tentativas depois de 30 s, 2 min e 5 min se o servidor ou a rede falharem: `source.fetch_with_retries`), e escreve `data/landing/dgeg/AAAA-MM-DD.parquet`. A DGEG só mostra o preço em vigor: o histórico é o ramo `dados` (`dgeg/*.parquet`), escrito pelo `dgeg.yml` todas as segundas-feiras (diário de 28/10 a 2/11/2026) e lido pelo `pages.yml`, que já não pede nada à DGEG e corre também a seguir ao `dgeg.yml` (`workflow_run`). Nunca reescrever esse ramo. Vigilância (`check.py`, `combustiveis verificar-dgeg`): o `dgeg.yml` falha depois de guardar se a fotografia de hoje tiver menos 20 % de postos do que a anterior, e o trabalho `vigilancia` do `pages.yml` (à parte do build, para o site ser publicado na mesma) falha se a última fotografia do ramo `dados` tiver mais de 8 dias. As falhas chegam por email. A leitura (`dgeg.py`) valida a resposta (lança `DgegFormatError`), como o `parse.py`. Termos do portal: identificar a DGEG, mostrar a data e hora de atualização de cada preço e não alterar os preços; as médias excluem os preços com mais de 30 dias (`is_current`), mas os dados guardam tudo. Os testes usam `tests/fixtures/dgeg_sample.json` (`scripts/make_dgeg_sample.py`). Grupos de marcas no seed `dgeg_brand_segments` (o resto é "Outras marcas"). O mapa do painel usa os mosaicos do OpenStreetMap (`tile.openstreetmap.org`, com a atribuição; uso gratuito para pouco tráfego). Os da CARTO, que o Evidence usa por omissão, passaram a pedir uma chave de API (aparece "API KEY REQUIRED" no mapa). Nas sessões cloud, o domínio dos mosaicos tem de estar nos permitidos, senão o mapa aparece sem fundo. O `build:strict` falha com uma tabela ou um gráfico sem dados: o CI usa a amostra (37 postos, fotografia fixa de 28/10/2026, para os preços não ficarem com mais de 30 dias), por isso o que puder ficar vazio leva `emptySet="pass"` e `emptyMessage`. Concorrência: `int_station_neighbours` conta os postos a 2 e 5 km com a fórmula de haversine em SQL (sem a extensão espacial, que o CI teria de descarregar); análise em `docs/analises/concorrencia-postos.md`. Filtros da página: distrito e concelho com `like` e a opção "Todos" = `%` (os nomes não têm apóstrofos). Postos acompanhados (página `app/acompanhados/`, ADR 0006): os ids da DGEG no seed `tracked_stations`; os concorrentes a 5 km vêm de `int_tracked_station_neighbours`, e o `scripts/make_dgeg_sample.py` junta à amostra cada posto acompanhado e os três mais próximos (um posto novo no seed pede outra amostra). No mapa (Leaflet), os concorrentes pela cor do preço (quintis) e o posto a vermelho. O mapa da página dos postos é um componente próprio (`dashboard/components/MapaPostos.svelte`, com o Leaflet que vem com o Evidence), porque os mapas do Evidence não dão os limites à página: a tabela por baixo fica com os postos que se veem, do mais barato para o mais caro. O componente só reenquadra o mapa quando as linhas mudam (o store da consulta emite as mesmas linhas mais de uma vez), e marca `data-postos` quando já desenhou, para os testes esperarem por isso. "Perto de mim" usa a localização do browser (nos testes, `context.setGeolocation`), e "Ir" abre o Google Maps (`/maps/dir/?api=1&destination=lat,long`). O contentor do mapa tem `isolation: isolate`, senão o Leaflet passa por cima do cabeçalho fixo. A coluna "Na semana" e o histórico do balão ("Últimas fotografias", "Última mudança de preço") vêm de `int_station_price_changes` (preço e dia da fotografia anterior, preço de há 7 dias, último dia em que mudou e as últimas 5 fotografias em texto, `recent_history`), juntas ao `rpt_stations_latest`. Com a localização, a coluna "Poupa" compara um depósito em cada posto com o posto mais perto, descontando a ida e volta (linha reta × 1,3, `ROAD_FACTOR`); o depósito e o consumo ficam no `localStorage` (`combustiveis-pt:poupanca`, com `try/catch`), e a tabela pode ordenar-se por poupança. A estrela de cada linha guarda o posto em "Os meus postos" (topo do componente), pelo id da DGEG, no `localStorage` (`combustiveis-pt:favoritos`); a lista usa as linhas da zona escolhida e avisa quando algum favorito fica de fora; cada favorito mostra a posição entre os postos a 5 km dessas linhas (`competition`, haversine no browser; um empate não conta como mais barato) e o mais barato à volta. Até ao zoom 11 (`GROUP_UNTIL_ZOOM`), os pontos juntam-se numa grelha de 56 px (`drawMarkers`, redesenhada a cada zoom): os grupos são `divIcon` (`.grupo-postos`) no centro do quadrado, para não se sobreporem (o axe falha com `target-size`), com a cor do preço mediano e o texto a preto ou branco, o que tiver mais contraste (`ink`); tocar num grupo aproxima o mapa. O `focus` muda o zoom sem animação, para os postos soltos já estarem desenhados quando abre o balão, e traz o mapa ao ecrã.
