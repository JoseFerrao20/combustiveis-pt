# combustiveis-pt

Pipeline de dados com os preços semanais dos combustíveis em Portugal e na UE (Weekly Oil Bulletin da Comissão Europeia, desde 2005): ingestão em Python para Parquet (`src/combustiveis/`), depois dbt com DuckDB e um site estático (Vite e Svelte, `dashboard/`, publicado no GitHub Pages pelo `pages.yml`). Projeto de portfólio de José Ferrão. A escolha da fonte está em `docs/adr/0001-fonte-weekly-oil-bulletin.md`; o histórico e o plano em `DEVLOG.md`.

## Comandos

```bash
uv sync --all-groups                           # o grupo transform traz o dbt
uv run pytest                                  # cobertura ≥ 90 %
uv run ruff check . && uv run ruff format --check . && uv run mypy
uv run combustiveis ingest                     # precisa de acesso a energy.ec.europa.eu
uv run combustiveis ingest --ficheiro tests/fixtures/oil_bulletin_sample.xlsx   # sem rede
uv run combustiveis dgeg [--ficheiro tests/fixtures/dgeg_sample.json]         # fotografia dos postos (DGEG)
uv run combustiveis verificar-dgeg [--pasta data/landing/dgeg] [--idade-maxima 8]   # histórico da DGEG em dia
uv run combustiveis mercados [--ficheiros tests/fixtures/fred]                # cotações e câmbio (FRED), para a previsão
uv run combustiveis ilhas [--pasta data/landing/ilhas]                        # preços máximos dos Açores e da Madeira (despachos novos em PDF)
uv run combustiveis verificar-ilhas                                            # há o preço da semana (Madeira) e do mês (Açores)?
uv run combustiveis telegram [--enviar]                                        # avisos de segunda-feira (TELEGRAM_SUBSCRIPTIONS e TELEGRAM_BOT_TOKEN; sem --enviar, só mostra)
uv run combustiveis verificar-site --url https://joseferrao20.github.io/combustiveis-pt/   # o site publicado está em ordem?
uv run combustiveis site                                                       # depois do dbt: os JSON da página inicial (dashboard/app/public/dados/), as páginas por concelho, o sitemap.xml e os dados abertos
uv run python scripts/fit_forecast.py [--gravar]                              # coeficientes da previsão (depois do dbt, com os dados reais)
uv run dbt build --project-dir transform --profiles-dir transform   # da raiz; LANDING_DIR, DGEG_DIR, DUCKDB_PATH e *_EXPORT_PATH mudam os caminhos
cd dashboard && npm ci && npm run build                       # o site (Vite, Node 22) em dashboard/build/, depois do dbt e do `site`
cd dashboard && npm run dev                                   # o site com o Vite, com os JSON do `site`
cd dashboard && npm test                                      # Playwright sobre o build (tests/serve.mjs serve /combustiveis-pt/)
```

## Convenções

- README, DEVLOG, ADR, mensagens de erro e descrições de PR em **português de Portugal**; nomes no código e mensagens de commit em inglês.
- Cada alteração num PR a partir de um ramo, com o CI verde.
- O formato do ficheiro do boletim não está documentado: a leitura (`parse.py`) valida-o e lança `FormatError` em vez de devolver dados errados. Os testes usam `tests/fixtures/oil_bulletin_sample.xlsx`, uma amostra do ficheiro real gerada com `scripts/make_sample.py`: se o formato mudar, gerar outra a partir do ficheiro novo.
- Valores por 1000 L (por tonelada nos fuelóleos). Nas folhas de impostos, uma célula vazia é "sem dados", não zero. O ISP e os outros impostos estão na moeda nacional (escudos antes de 2002).
- O link do ficheiro muda quando a Comissão o substitui: procurar sempre na página (`source.find_history_url`), nunca fixar o endereço.
- `data/` não entra no Git.
- DuckDB 2: as relações já não têm `fetchone()`; usar `fetchall()`.
- dbt (`transform/`): staging e intermediate são views, marts são tabelas. Testes com a sintaxe `arguments:` do dbt 1.10+. Os testes guardam as linhas que falham (`store_failures`), para se verem no DuckDB. Um erro na fonte não se corrige nos dados: entra no seed `known_source_errors` com a explicação, depois de visto.
- As tabelas de ISP e outros impostos só se comparam com o preço a partir de `countries.euro_since` (antes, estão na moeda nacional). A decomposição (`fct_fuel_prices`) vem dos preços e do IVA; as tabelas só dão o `tax_tables_gap`. Os períodos em que as tabelas estão erradas, já investigados, ficam no seed `known_tax_table_issues` (país, produto, de/até, explicação; sem sobreposições) e aparecem em `tax_tables_issue`; o aviso `warn_tax_tables_explain_price` (PT, LT, NL, SK e ES) ignora-os e está a zero: uma linha nova é uma semana a investigar. Análises em `docs/analises/`.
- DuckDB: um alias de coluna precisa de `as` quando o nome é uma palavra-chave (`count(*) as weeks`).
- Site (`dashboard/`, ADR 0008, que substitui a 0002 do Evidence): páginas estáticas com o Vite 5 e o Svelte 4 (versões fixadas nas `devDependencies`; o Leaflet é a única dependência), uma por entrada em `app/vite.config.mjs` (`PAGINAS`): a inicial (`app/index.html`), `resumo/`, `acompanhados/`, `ilhas/` e `analises/` (índice, `impostos/`, `previsao/`, `comparacao/`, `metodo/`). Cada página tem o seu `index.html` (título, descrição, `og:*`, ícones e manifesto) e um `src/<página>.js` que importa o `arranque.js` (tema e service worker) e monta o componente (`App`, `Resumo`, `Acompanhados`, `Ilhas`, `Analises`, `Impostos`, `Previsao`, `Comparacao`, `Metodo`). Sem DuckDB nem SQL no browser: as páginas leem só JSON pequenos de `dados/`, escritos pelo `combustiveis site` (`site.py`) a partir dos Parquet que o dbt exporta (modelos `rpt_*` em `transform/models/reporting/`); uma coluna ou uma análise nova entra nesses modelos e no `site.py`. `app/public/` vai tal e qual para a raiz do `build/`: ícones, `og.png`, `manifest.webmanifest`, `sw.js`, `estilos/concelho.css`, os redirecionamentos dos endereços antigos (`postos/`, `comparacao/`, `metodo/`) e o que o `combustiveis site` escreve (`dados/`, `concelho/`, `dados-abertos/`, `sitemap.xml`, fora do Git). Nas sessões cloud, o `npm` precisa de `NODE_USE_ENV_PROXY=1 NODE_EXTRA_CA_CERTS=/root/.ccr/ca-bundle.crt` (o Node não usa o `HTTPS_PROXY` sem isso).
- O site está em `/combustiveis-pt` (`base` no `app/vite.config.mjs`). Aspeto comum: o cabeçalho (`components/Cabecalho.svelte`: ícone, nome e os links Início, Resumo, Postos acompanhados, Açores e Madeira e Análises, com "Menu" até 760 px), o rodapé (`components/Rodape.svelte`) e o CSS (`app/src/base.css`: as cores dos dois temas, `.pagina`, `.filtros-pagina`, cartões `.cartoes`/`.cartao`/`.cartao-titulo`/`.cartao-numero`/`.cartao-texto` e `a.cartao`, `.seta-baixo`/`.seta-cima`, `.conclusao`, `.tabela`, `.rolar`, `details.mais-detalhes`, `.fonte`, e as classes do Tailwind que o mapa usa) servem todas as páginas; as páginas por concelho e os dados abertos (HTML do `pages.py`) têm uma cópia simples. O botão do tema (no cabeçalho e nas páginas por concelho) troca o claro e o escuro: muda o `data-theme` do `<html>` e guarda em `evidence-theme` (a chave do tempo do Evidence, mantida para quem já a tinha). As análises abrem pelos cartões do índice (`Analises.svelte`), cada um com o número principal. As tabelas secundárias ficam num `<details class="mais-detalhes">`. Números e datas em português com `toLocaleString('pt-PT')` (`formatos.js`: `euros`, `euros2`, `centimos`, `seta`, `pct`, `inteiro`, `quando`, `diaCurto`, `tabela`). No DuckDB (dbt), um alias da mesma `select` não se reutiliza numa expressão com subconsulta: usar uma consulta à volta.
- Página inicial (ADR 0005): `app/index.html` e `App.svelte`, com o `components/MapaPostos.svelte` (só a página inicial o usa). A página passa ao componente o combustível (slot `combustivel`, ao lado de "Perto de mim") e o distrito e o concelho (slot `zona`, dentro do "Filtros", um `<details>` com a marca, as autoestradas e, com a localização, o depósito e o consumo; `zoneFilters` conta os filtros da zona escolhidos para o resumo do "Filtros"). A previsão é uma linha (`forecast_summary` do `resumo.json`) que abre o texto todo. O cabeçalho é uma linha com "Menu" no telemóvel. Lê `dados/resumo.json` e `dados/postos-<combustível>.json`, escritos pelo `combustiveis site` (`site.py`, a partir de `stations_latest.parquet` e `price_forecast.parquet`; colunas em `COLUMNS`, horas com `Z`: a hora de Lisboa escrita como UTC). O código comum das páginas fica em `build/inicio/`. Resumo e postos acompanhados (ADR 0006): `app/resumo/` e `app/acompanhados/`. O resumo calcula as médias no browser a partir de `dados/postos-<combustível>.json` (por isso o `COLUMNS` leva `brand_segment` e `competitors_5km`) e a evolução de `dados/evolucao.json`; os postos acompanhados leem `dados/acompanhados.json`. Os dois JSON vêm do `combustiveis site` (`export_history`, `export_tracked`, a partir de `station_prices_daily`, `tracked_stations_daily` e `tracked_station_competitors`; sem os Parquet, não os escreve). Os gráficos são SVG sem bibliotecas: `Grafico.svelte` (linhas, ou áreas com `empilhado`; `minimo` fixa o fundo do eixo; com mais de 60 datas, sem círculos, rótulos por ano e a tabela `sr-only` com a média de cada ano; a primeira série fica por cima) e `GraficoBarras.svelte` (barras agrupadas à volta do zero, na previsão); os filtros são `<select>` nativos com `label` (nos testes, `getByRole('combobox', { name: 'Distrito' })`). Análises (ADR 0008): `dados/boletim.json` (`export_analyses`: Portugal com a divisão do preço em todas as semanas, Espanha e a média da UE, e todos os países na última semana, em listas com `columns`, lidas com `tabela`; e a data da última descarga do `manifest.json`) e `dados/previsao.json`; as contas (erro médio, acerto do sentido, posição de Portugal) fazem-se no browser. O produto escolhido nas análises fica em `combustiveis-pt:produto`. Açores e Madeira (ADR 0007): `app/ilhas/`, com `dados/ilhas.json` (`export_islands`, de `island_prices.parquet`). Um `.sr-only` nunca vai numa `<table>` (uma tabela não encolhe para 1 px e a página passa a deslizar para o lado no telemóvel): vai numa `div` à volta. Uma classe nova do Tailwind no `MapaPostos.svelte` tem de entrar no `base.css`; o componente recebe as linhas num store (`data`). Links: a página inicial aceita `?posto=<id da DGEG>`, `?combustivel=`, `?distrito=` e `?concelho=` (aplicados depois de ler o resumo; o concelho escolhe também o distrito). Um posto do link abre o balão, sem a localização lembrada; "Partilhar" (no balão, `partilhar`) usa o `navigator.share` ou copia o link. Páginas por concelho (`pages.py`, escritas pelo `combustiveis site` em `app/public/concelho/`, pasta apagada e refeita em cada execução, e `app/public/sitemap.xml`): HTML estático com os 10 mais baratos de cada combustível, a data e a hora de cada preço (termos da DGEG), as médias do concelho, do distrito e do país e "Ver todos no mapa" (`?concelho=`); o estilo está em `app/public/estilos/concelho.css` (fora de `concelho/`, que é apagada). Dados abertos (`opendata.py`, em `app/public/dados-abertos/`, com `--armazem`, por omissão `data/warehouse.duckdb`; sem ele, não se escrevem): `postos-historico.csv.gz` (todas as fotografias, `fct_station_prices`), `postos-ultima-fotografia.csv` e `boletim-europeu.csv.gz` (`fct_fuel_prices`, com os valores arredondados a 2 casas e as partes a 4), e a página com as colunas, as fontes e como citar (feita com o `_page` das páginas por concelho). Instalar como aplicação: `app/public/manifest.webmanifest` (nome, `start_url`, `display: standalone`, `shortcuts`). Pouca rede: `app/public/sw.js` (a página inicial, as páginas leves de `LIGHT_PAGES` e os `dados/*.json`: rede primeiro, sem a cache HTTP; o que ficou guardado se falhar ou demorar 4 s, com o cabeçalho `x-combustiveis-guardado`; os ficheiros de `inicio/` primeiro da cache). Uma página nova entra em `LIGHT_PAGES`. Nos testes, o modo offline do Playwright nem sempre chega ao service worker: a página também mostra o aviso com `navigator.onLine` falso, e o teste confirma o que ficou na cache.
- Agendamento: o `pages.yml` corre todos os dias (cron em UTC) com `ingest --idade-maxima 15`, que falha se o boletim tiver parado. Uma falha não publica nada: o site fica com a última versão boa. Depois do deploy, o trabalho `verificar` corre `combustiveis verificar-site` (`live.py`) com o endereço publicado: a página inicial, `dados/resumo.json` com uma fotografia de no máximo 8 dias e postos em todos os combustíveis, o JSON do primeiro combustível com os postos que o resumo diz, `resumo/`, `concelho/`, `dados-abertos/` com o link do histórico, o `sitemap.xml` com os concelhos, `sw.js` e o manifesto. Junta todos os problemas numa mensagem (o email do GitHub). Os pedidos usam o `fetch_with_retries`; nos testes, o `fetch` é um site em memória.
- Açores e Madeira (ADR 0007, `ilhas.py`): a DGEG só tem o continente; nas regiões autónomas há um preço máximo da gasolina 95 e do gasóleo, fixado pelo governo regional e publicado em PDF. Madeira: despacho conjunto semanal na II série do JORAM (quase sempre num suplemento de sexta, mas pode sair noutro dia), em vigor na segunda; lê-se a lista de cada ano (`MADEIRA_LISTING`) e, de cada PDF novo, primeiro só o sumário (`SUMMARY_PAGES`, há números com dezenas de MB). Açores: despacho normativo mensal na I série do Jornal Oficial, em vigor no dia 1; o site tem uma verificação anti-robôs (não contornar), mas os PDFs dos números têm endereços sequenciais (`ACORES_ISSUE`, `I-AAAA-NNN-S0.pdf`, com o índice e os atos), seguidos até ao primeiro 404. Texto com o pypdfium2 (`pdf_text`, numa linha e em minúsculas), frases fixas em expressões regulares, preços validados (`PRICE_RANGE`) e a data de entrada em vigor face à publicação; o que não se lê lança `IslandFormatError` e o `update` para antes desse ficheiro (o estado fica lá, para o reler depois de corrigido). Histórico no ramo `dados` (`ilhas/precos.csv` e `ilhas/estado.json`), escrito pelo `ilhas.yml` todos os dias, que depois corre `verificar-ilhas` (falha sem o preço da semana na Madeira, mais de 8 dias, ou do mês nos Açores, depois do dia 3); o `pages.yml` tira-o do ramo, ou escreve um CSV só com o cabeçalho. dbt: fonte `ilhas` (`ILHAS_DIR`), `stg_ilhas__max_prices` e `rpt_island_prices` (com o preço médio dos postos do continente na última fotografia de cada período). O CI usa `tests/fixtures/ilhas/precos.csv` (despachos reais de setembro a novembro de 2026). Nos testes, os PDFs fazem-se com `make_pdf` (Helvetica com WinAnsi, que tem o € e os acentos).
- Avisos pelo Telegram (`telegram.py`, guia em `docs/telegram.md`): o `pages.yml` corre `combustiveis telegram --enviar` só a seguir a uma fotografia da DGEG bem tirada (`workflow_run` com `conclusion == 'success'`), com `continue-on-error` (o Telegram não impede a publicação). As inscrições estão no segredo `TELEGRAM_SUBSCRIPTIONS` (JSON: `chat_id`, `combustivel`, `postos`, `distrito`) e o token em `TELEGRAM_BOT_TOKEN`; sem eles, não envia nada. A mensagem é texto simples (o Telegram faz os links), com a previsão, os postos seguidos (preço, mudança na semana, posição a 5 km em haversine, como no site) e o mais barato do distrito (`of_district`: "do Porto", "da Guarda"). O envio continua se uma mensagem falhar e diz no fim quais falharam. Nos testes, o `_post` é simulado; a função escolhe-se dentro do `send` (`post=None`), para o `monkeypatch` a trocar.
- Cores das séries: nas próprias páginas (por exemplo, `CORES` em `Comparacao.svelte` e `Ilhas.svelte`), com contraste nos dois temas.
- Ver o site: depois do build, servir a pasta pai de um link `combustiveis-pt → dashboard/build` (`python3 -m http.server`) e abrir `/combustiveis-pt/`; as páginas são pastas (`analises/comparacao/`). Os endereços antigos (`postos/`, `comparacao/`, `metodo/`) redirecionam com páginas HTML em `app/public/`.
- Interface em português: cada `index.html` tem `lang="pt-PT"` (um teste confirma-o em todas as páginas). As capturas do README (`docs/images/painel-*.png`, 1280×860, tema claro) tiram-se com o Playwright; as das páginas leves e das análises com `node scripts/capturas.cjs <endereço do site>` (pasta `dashboard/`, com os dados reais). A manutenção (o que corre, os avisos e o que fazer) está em `docs/manutencao.md`: um workflow ou um aviso novo entra lá.
- Postos (ADR 0003): `combustiveis dgeg` lê a API JSON da página de pesquisa da DGEG (`/api/PrecoComb/PesquisarPostos`, sem documentação), num pedido só (com novas tentativas depois de 30 s, 2 min e 5 min se o servidor ou a rede falharem: `source.fetch_with_retries`), e escreve `data/landing/dgeg/AAAA-MM-DD.parquet`. A DGEG só mostra o preço em vigor: o histórico é o ramo `dados` (`dgeg/*.parquet`), escrito pelo `dgeg.yml` todas as segundas-feiras (diário de 28/10 a 2/11/2026) e lido pelo `pages.yml`, que já não pede nada à DGEG e corre também a seguir ao `dgeg.yml` (`workflow_run`). Nunca reescrever esse ramo. Vigilância (`check.py`, `combustiveis verificar-dgeg`): o `dgeg.yml` falha depois de guardar se a fotografia de hoje tiver menos 20 % de postos do que a anterior, e o trabalho `vigilancia` do `pages.yml` (à parte do build, para o site ser publicado na mesma) falha se a última fotografia do ramo `dados` tiver mais de 8 dias. As falhas chegam por email. A leitura (`dgeg.py`) valida a resposta (lança `DgegFormatError`), como o `parse.py`. Termos do portal: identificar a DGEG, mostrar a data e hora de atualização de cada preço e não alterar os preços; as médias excluem os preços com mais de 30 dias (`is_current`), mas os dados guardam tudo. Os testes usam `tests/fixtures/dgeg_sample.json` (`scripts/make_dgeg_sample.py`). Grupos de marcas no seed `dgeg_brand_segments` (o resto é "Outras marcas"). Os mapas usam os mosaicos do OpenStreetMap (`tile.openstreetmap.org`, com a atribuição; uso gratuito para pouco tráfego). Nas sessões cloud, o domínio dos mosaicos tem de estar nos permitidos, senão o mapa aparece sem fundo. O CI usa a amostra (37 postos, fotografia fixa de 28/10/2026, para os preços não ficarem com mais de 30 dias, e 5 semanas do boletim): o que puder ficar vazio diz isso na página, em vez de uma tabela ou um gráfico sem nada. Concorrência: `int_station_neighbours` conta os postos a 2 e 5 km com a fórmula de haversine em SQL (sem a extensão espacial, que o CI teria de descarregar); análise em `docs/analises/concorrencia-postos.md`. Postos acompanhados (página `app/acompanhados/`, ADR 0006): os ids da DGEG no seed `tracked_stations`; os concorrentes a 5 km vêm de `int_tracked_station_neighbours`, e o `scripts/make_dgeg_sample.py` junta à amostra cada posto acompanhado e os três mais próximos (um posto novo no seed pede outra amostra). No mapa (Leaflet), os concorrentes pela cor do preço (quintis) e o posto a vermelho. O mapa da página inicial é `dashboard/components/MapaPostos.svelte` (Leaflet): a tabela por baixo fica com os postos que se veem, do mais barato para o mais caro. O componente só reenquadra o mapa quando as linhas mudam (o store pode emitir as mesmas linhas mais de uma vez), e marca `data-postos` quando já desenhou, para os testes esperarem por isso. "Perto de mim" usa a localização do browser (nos testes, `context.setGeolocation`), e "Ir" abre o Google Maps (`/maps/dir/?api=1&destination=lat,long`). O contentor do mapa tem `isolation: isolate`, senão o Leaflet passa por cima do cabeçalho fixo. A coluna "Na semana" e o histórico do balão ("Últimas fotografias", "Última mudança de preço") vêm de `int_station_price_changes` (preço e dia da fotografia anterior, preço de há 7 dias, último dia em que mudou e as últimas 5 fotografias em texto, `recent_history`), juntas ao `rpt_stations_latest`. Com a localização, a coluna "Poupa" compara um depósito em cada posto com o posto mais perto, descontando a ida e volta (linha reta × 1,3, `ROAD_FACTOR`); o depósito e o consumo ficam no `localStorage` (`combustiveis-pt:poupanca`, com `try/catch`), e a tabela pode ordenar-se por poupança. A estrela de cada linha guarda o posto em "Os meus postos" (topo do componente), pelo id da DGEG, no `localStorage` (`combustiveis-pt:favoritos`); a lista usa as linhas da zona escolhida e avisa quando algum favorito fica de fora; cada favorito mostra a posição entre os postos a 5 km dessas linhas (`competition`, haversine no browser; um empate não conta como mais barato) e o mais barato à volta. Até ao zoom 11 (`GROUP_UNTIL_ZOOM`), os pontos juntam-se numa grelha de 56 px (`drawMarkers`, redesenhada a cada zoom): os grupos são `divIcon` (`.grupo-postos`) no centro do quadrado, para não se sobreporem (o axe falha com `target-size`), com a cor do preço mediano e o texto a preto ou branco, o que tiver mais contraste (`ink`); tocar num grupo aproxima o mapa. O `focus` muda o zoom sem animação, para os postos soltos já estarem desenhados quando abre o balão, e traz o mapa ao ecrã. A partir de 1024 px, o mapa (fixo, quase da altura do ecrã) e a lista ficam lado a lado (`.corpo`); a lista esconde as colunas `larga` (#, marca, concelho, data, que passam para a linha de baixo) e mantém as `media` ("Na semana", "Distância"), que só saem no telemóvel. Nos testes, a distância é `td.distancia`. Até 640 px, a lista e o mapa são separadores ("Lista"/"Mapa", `view`): o mapa escondido fica fora do ecrã com o mesmo tamanho (`.fora`, com `inert`), e não com `display: none`, porque a lista são os postos da parte do mapa que se vê; "Ver no mapa" muda para o mapa. Localização lembrada: depois do primeiro "Perto de mim", `combustiveis-pt:localizacao` faz a página abrir já ali (só com a autorização do browser, ou se a API das permissões não existir; nunca com "denied"), e "Não abrir aqui" esquece. Com a localização, a lista pode ordenar-se por preço, distância ou poupança. Nomes: `tidy` tira as maiúsculas todas da DGEG (as siglas curtas sem vogais e os números romanos ficam), `brandLabel` mostra "Genérico" como "Sem marca", e a linha de baixo no telemóvel só repete a marca se não estiver no nome. Datas curtas (`whenShort`: "hoje, 12:25", "ontem, …" ou "28/10, 08:35", sempre com a hora, como pedem os termos da DGEG; o balão tem a data completa) e um aviso com mais de 7 dias. A mudança na semana leva a unidade ("▼ 2,0 c").
