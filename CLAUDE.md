# combustiveis-pt

Pipeline de dados com os preços semanais dos combustíveis em Portugal e na UE (Weekly Oil Bulletin da Comissão Europeia, desde 2005): ingestão em Python para Parquet (`src/combustiveis/`), depois dbt com DuckDB e um painel com Evidence (`dashboard/`, publicado no GitHub Pages pelo `pages.yml`). Projeto de portfólio de José Ferrão. A escolha da fonte está em `docs/adr/0001-fonte-weekly-oil-bulletin.md`; o histórico e o plano em `DEVLOG.md`.

## Comandos

```bash
uv sync --all-groups                           # o grupo transform traz o dbt
uv run pytest                                  # cobertura ≥ 90 %
uv run ruff check . && uv run ruff format --check . && uv run mypy
uv run combustiveis ingest                     # precisa de acesso a energy.ec.europa.eu
uv run combustiveis ingest --ficheiro tests/fixtures/oil_bulletin_sample.xlsx   # sem rede
uv run combustiveis dgeg [--ficheiro tests/fixtures/dgeg_sample.json]         # fotografia dos postos (DGEG)
uv run dbt build --project-dir transform --profiles-dir transform   # da raiz; LANDING_DIR, DGEG_DIR, DUCKDB_PATH e *_EXPORT_PATH mudam os caminhos
cd dashboard && npm ci && npm run sources && npm run build   # painel (Evidence, Node 22), depois do dbt
cd dashboard && npm test                                      # Playwright sobre o build (tests/serve.mjs serve /combustiveis-pt/)
```

## Convenções

- README, DEVLOG, ADR, mensagens de erro e descrições de PR em **português de Portugal**; nomes no código e mensagens de commit em inglês.
- Cada alteração num PR a partir de um ramo, com o CI verde.
- O formato do ficheiro do boletim não está documentado: a leitura (`parse.py`) valida-o e lança `FormatError` em vez de devolver dados errados. Os testes usam `tests/fixtures/oil_bulletin_sample.xlsx`, uma amostra do ficheiro real gerada com `scripts/make_sample.py`: se o formato mudar, gerar outra a partir do ficheiro novo.
- Valores por 1000 L (por tonelada nos fuelóleos). Nas folhas de impostos, uma célula vazia é "sem dados", não zero. O ISP e os outros impostos estão na moeda nacional (escudos antes de 2002).
- O link do ficheiro muda quando a Comissão o substitui: procurar sempre na página (`source.find_history_url`), nunca fixar o endereço.
- `data/` não entra no Git.
- DuckDB 2: as relações já não têm `fetchone()`; usar `fetchall()`.
- dbt (`transform/`): staging e intermediate são views, marts são tabelas. Testes com a sintaxe `arguments:` do dbt 1.10+. Os testes guardam as linhas que falham (`store_failures`), para se verem no DuckDB. Um erro na fonte não se corrige nos dados: entra no seed `known_source_errors` com a explicação, depois de visto.
- As tabelas de ISP e outros impostos só se comparam com o preço a partir de `countries.euro_since` (antes, estão na moeda nacional). A decomposição (`fct_fuel_prices`) vem dos preços e do IVA; as tabelas só dão o `tax_tables_gap`. Os períodos em que as tabelas estão erradas, já investigados, ficam no seed `known_tax_table_issues` (país, produto, de/até, explicação; sem sobreposições) e aparecem em `tax_tables_issue`; o aviso `warn_tax_tables_explain_price` (PT, LT, NL, SK e ES) ignora-os e está a zero: uma linha nova é uma semana a investigar. Análises em `docs/analises/`.
- DuckDB: um alias de coluna precisa de `as` quando o nome é uma palavra-chave (`count(*) as weeks`).
- Painel (`dashboard/`, ADR 0002): Evidence open source 40.1.8, versões fixadas; já não recebe novidades (a empresa passou para o Evidence Studio). Lê só os Parquet que o dbt exporta (modelos `rpt_*` em `transform/models/reporting/`: `data/road_fuel_prices.parquet`, `data/stations_latest.parquet`, `data/station_prices_daily.parquet`, `data/tracked_stations_daily.parquet` e `data/tracked_station_competitors.parquet`), porque o DuckDB do Evidence (1.4) não abre a base de dados do DuckDB 2. Uma coluna nova para o painel entra nesses modelos. O `npm run sources` e o `npm run build` precisam de `extensions.duckdb.org` (o DuckDB-WASM descarrega aí a extensão de Parquet): sem acesso, ficam parados em vez de falhar. Nas sessões cloud, com o proxy, correr com `NODE_USE_ENV_PROXY=1 NODE_EXTRA_CA_CERTS=/root/.ccr/ca-bundle.crt` (o Node não usa o `HTTPS_PROXY` sem isso). O `typescript` fica na 5.4.2, a versão que o Evidence pede.
- O site está em `/combustiveis-pt` (`deployment.basePath`): os links entre páginas passam pela barra lateral do Evidence, não por links escritos à mão.
- Agendamento: o `pages.yml` corre todos os dias (cron em UTC) com `ingest --idade-maxima 15`, que falha se o boletim tiver parado. Uma falha não publica nada: o site fica com a última versão boa.
- Números do painel em português (`2,099 €`, `58,8%`): o `ssf` do Evidence não tem locales, por isso há um patch (`dashboard/patches/`, aplicado pelo `patch-package` no `postinstall`) que troca os separadores na formatação dos números. Se a versão do `@evidence-dev/component-utilities` mudar, o patch tem de ser refeito. As cores das séries estão nas páginas (`seriesColors`, `colorPalette`), e o título e o link do repositório em `pages/+layout.svelte`.
- Ver o painel: depois do build, servir a pasta pai de um link `combustiveis-pt → dashboard/build` (`python3 -m http.server`) e abrir `/combustiveis-pt/`; as páginas são pastas (`analises/comparacao/`). Páginas: `index.md` (os postos, a página para a família e os amigos), `acompanhados.md` e a pasta `analises/` (impostos, comparação com a Europa e método; a barra lateral agrupa-as pelo `analises/index.md`). Os endereços antigos (`postos/`, `comparacao/`, `metodo/`) redirecionam com páginas HTML em `static/`. Uma página sem consultas faz o Evidence pedir um `all-queries.json` que não existe (404 nos testes): pôr pelo menos uma consulta.
- Interface em português: o patch `dashboard/patches/@evidence-dev+core-components+5.4.2.patch` traduz o menu ("Aspeto", "Imprimir em PDF"), a pesquisa e a paginação das tabelas e o "Feito com o Evidence"; o `@evidence-dev+evidence+40.1.8.patch` põe `lang="pt-PT"` no `app.html`. O `+layout.svelte` tem `neverShowQueries` (esconde "Show Queries"). Textos novos do Evidence em inglês entram nesses patches (editar em `node_modules/` e correr `npx patch-package <pacote>`). As capturas do README (`docs/images/painel-*.png`, 1280×860, tema claro) tiram-se assim com o Playwright. A barra lateral usa o `title` de cada página; o CSS em `+layout.svelte` tira o `capitalize` do Evidence, e o caminho de navegação está desligado (dizia sempre "Home").
- Postos (ADR 0003): `combustiveis dgeg` lê a API JSON da página de pesquisa da DGEG (`/api/PrecoComb/PesquisarPostos`, sem documentação), num pedido só, e escreve `data/landing/dgeg/AAAA-MM-DD.parquet`. A DGEG só mostra o preço em vigor: o histórico é o ramo `dados` (`dgeg/*.parquet`), escrito pelo `dgeg.yml` todos os dias e lido pelo `pages.yml`. Nunca reescrever esse ramo. A leitura (`dgeg.py`) valida a resposta (lança `DgegFormatError`), como o `parse.py`. Termos do portal: identificar a DGEG, mostrar a data e hora de atualização de cada preço e não alterar os preços; as médias excluem os preços com mais de 30 dias (`is_current`), mas os dados guardam tudo. Os testes usam `tests/fixtures/dgeg_sample.json` (`scripts/make_dgeg_sample.py`). Grupos de marcas no seed `dgeg_brand_segments` (o resto é "Outras marcas"). O mapa do painel usa os mosaicos do OpenStreetMap (`tile.openstreetmap.org`, com a atribuição; uso gratuito para pouco tráfego). Os da CARTO, que o Evidence usa por omissão, passaram a pedir uma chave de API (aparece "API KEY REQUIRED" no mapa). Nas sessões cloud, o domínio dos mosaicos tem de estar nos permitidos, senão o mapa aparece sem fundo. O `build:strict` falha com uma tabela ou um gráfico sem dados: o CI usa a amostra (37 postos, fotografia fixa de 28/10/2026, para os preços não ficarem com mais de 30 dias), por isso o que puder ficar vazio leva `emptySet="pass"` e `emptyMessage`. Concorrência: `int_station_neighbours` conta os postos a 2 e 5 km com a fórmula de haversine em SQL (sem a extensão espacial, que o CI teria de descarregar); análise em `docs/analises/concorrencia-postos.md`. Filtros da página: distrito e concelho com `like` e a opção "Todos" = `%` (os nomes não têm apóstrofos). Postos acompanhados (página `acompanhados.md`): os ids da DGEG no seed `tracked_stations`; os concorrentes a 5 km vêm de `int_tracked_station_neighbours`, e o `scripts/make_dgeg_sample.py` junta à amostra cada posto acompanhado e os três mais próximos (um posto novo no seed pede outra amostra). No mapa, `BaseMap` com dois `Points`: os concorrentes pela cor do preço e o posto a vermelho. O mapa da página dos postos é um componente próprio (`dashboard/components/MapaPostos.svelte`, com o Leaflet que vem com o Evidence), porque os mapas do Evidence não dão os limites à página: a tabela por baixo fica com os postos que se veem, do mais barato para o mais caro. O componente só reenquadra o mapa quando as linhas mudam (o store da consulta emite as mesmas linhas mais de uma vez), e marca `data-postos` quando já desenhou, para os testes esperarem por isso. "Perto de mim" usa a localização do browser (nos testes, `context.setGeolocation`), e "Ir" abre o Google Maps (`/maps/dir/?api=1&destination=lat,long`). O contentor do mapa tem `isolation: isolate`, senão o Leaflet passa por cima do cabeçalho fixo. A coluna "Desde ontem" e o histórico do balão ("Últimos dias", "Última mudança de preço") vêm de `int_station_price_changes` (preço da fotografia anterior, de há 7 dias, último dia em que mudou e `history_7d` em texto), juntas ao `rpt_stations_latest`. Abaixo de 640 px, a tabela esconde as colunas `larga` e põe a marca, o concelho e a data debaixo do nome.
- Partilha e ícones: cada página tem `description` e `og.image` no frontmatter (a imagem com o endereço completo, `https://…/og.png`, porque o WhatsApp não aceita caminhos relativos). `dashboard/static/` substitui os ícones do Evidence: o desenho está em `static/icon.svg`, e `node scripts/icons.cjs` gera os PNG e o `favicon.ico`; `node scripts/og.cjs <endereço da página dos postos>` gera a `og.png` (1200×630) com o painel a correr. Não pôr um `manifest.webmanifest` em `static/`: o Evidence já o gera (rota própria) e o build falha.
- Testes do painel (`dashboard/tests/pages.spec.mjs`, `@playwright/test` fixado na 1.64.1, a primeira com o Ubuntu 26.04 dos runners do GitHub; nas sessões cloud, o `playwright.config.mjs` usa o Chromium de `PW_CHROMIUM_PATH`, de outra versão): só verificam a forma, para passarem com a amostra e com os dados reais. O `npm test` serve o build com `tests/serve.mjs`; aqui, sem os mosaicos do mapa, a espera pelo `networkidle` demora mais. As listas dos filtros (Dropdown) só desenham as primeiras opções.
